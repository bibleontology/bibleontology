# Merge a reviewed explanation with the facts the reviewer lacked

A Bible study site explains links between New and Old Testament verses. Each
explanation below went to a critical reviewer, who returned `objections` and a
`revision`. Some objections were right. Others only said a statement "cannot
be checked" because the reviewer was not given a verse, or because an
"only"/"no other"/count claim reached beyond the verses supplied. Those
statements may be true, and removing true statements makes the site less
useful.

You now have what the reviewer lacked:
- `verses` -- the Berean Standard Bible text of every verse either text cites
  (some extra verses are noise from reference matching; ignore them);
- `facts` -- phrases searched by machine across every verse of the Berean Old
  Testament (or Revelation, where said), with the verses found. These are
  exact counts and can be relied on.

For each item write the final explanation:

1. Start from the `revision`. Keep every fix it makes for an objection that
   is about something other than checkability: a wrong quote, wrong wording,
   an overstatement ("nearly identical" where the verbs differ), a claim about
   what an author meant or did with the text, a gloss that takes a
   theological side, a kind change.
2. Restore a statement from the `original` that the revision removed ONLY
   because it could not be checked, when `verses` or `facts` now show it
   true. Word an "only" claim exactly as far as the facts go: "In the Old
   Testament the words "new covenant" occur only at Jer 31:31" is fine when
   the facts list one verse. If the facts show the claim false or narrower,
   correct it or leave it out.
3. Quote only the Berean, exactly, from `verses`, with the reference. Write
   references in the form "Heb 8:8". Say what the texts do, never what an
   author intended, and never what a text "fulfils" or "foreshadows" in the
   site's own voice. For prophecy (Daniel, Revelation and the like) state
   only what each text says.
4. 2-4 sentences. As informative as the original wherever the facts allow.

If `kind_should_be` is set, keep it unless the verses plainly show the
reviewer was wrong, and say why in `note`.

## Output

Write `M_out.json` in the same folder as `M_in.json`: a JSON list, same
order, one entry per item:

```json
[{"id": 0, "kind": "<final kind>", "explanation": "<final text>",
  "restored": ["<each statement restored, and the fact or verse that shows it>"],
  "note": "<anything else, or null>"}]
```

Valid JSON only; count the entries. Write no other files.
